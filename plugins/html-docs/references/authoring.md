# Authoring rules

How to produce the file so it works everywhere and stays faithful to the system.

## Self-contained, always

- **Inline everything.** All CSS in one `<style>`, all JS in one `<script>`. No
  external stylesheets, fonts, scripts, or network requests — the file must open
  from disk with zero dependencies, and Artifact surfaces enforce a strict CSP.
- **Embed assets as `data:` URIs.** No remote images.
- **Keep the reusable script.** The tabs + copy-to-clipboard JS in
  `template.html` is safe to ship in every document; don't strip it.

## Faithful to the system

- Copy `${CLAUDE_PLUGIN_ROOT}/assets/template.html` and keep its `<style>` block
  **verbatim**. Build the body from the documented component classes. Never
  hand-roll ad-hoc CSS or introduce off-palette colours — if you need something
  new, add a token to `:root` first (see `design-system.md`).
- Serif headings + system-sans body + clay accent is the signature. Don't swap
  the type or accent to "improve" it; that breaks consistency across documents.

## Reproducible

- Put the originating prompt in the leading HTML comment **and** the `.prompt-box`
  so the document can be regenerated by pasting it back. These artifacts are cheap,
  re-runnable probes — the prompt is what makes them re-runnable.

## Responsive & printable

- Use the `.grid-*` helpers (they collapse) and wrap wide tables in `.table-scroll`.
  The page body must never scroll horizontally. A print stylesheet is included.

## Where the file goes

- **Terminal (Claude Code):** there's no live artifact panel, so write the file to
  disk, tell the user the path, and offer to open it (`open <path>` on macOS) — the
  blog's whole workflow is opening these in a browser and sharing the file.
  - **Inside a git repo →** write to `<repo-root>/artifacts/<name>.html`. Create the
    dir with a self-ignoring `artifacts/.gitignore` whose only line is `*`, so
    generated docs never surface in `git status` or get committed. Use the repo the
    document is *about* when that differs from the cwd.
  - **No repo (or the cwd isn't one) →** fall back to `~/claude-artifacts/<name>.html`
    (create the dir once) rather than dropping files into an arbitrary directory.
- **Desktop / Web (Artifact tool available):** render it as an artifact so the user
  sees it live. Load the `artifact-design` skill first for anything design-heavy.
- The user "very often" wants several small documents for different parts/stages
  rather than one giant file — prefer a focused doc per concern over a monolith.

## Defer, don't duplicate

- **Charts / plots / dashboards →** the `dataviz` skill owns visualization; read it
  before writing chart code. This plugin styles the *document*, not the chart.
- **Deep design fundamentals →** the shipped `artifact-design` skill.
- This plugin's job is narrow: a consistent document shell + components so the
  model decides *what* to say, not *how* to build the page.
