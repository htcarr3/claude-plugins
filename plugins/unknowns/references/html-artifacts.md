# Producing an HTML artifact

Several skills in this plugin represent their output as a self-contained HTML
page. The point is a thing you can *react to* — click through a mockup, read a
plan, take a quiz — not a wall of prose. Follow these conventions so the output
works the same on every surface.

## Where the output goes

- **On a surface with an Artifact tool** (Claude Desktop / Web): render it as an
  artifact so the user sees it live. If you're doing anything beyond a trivial
  page, load the `artifact-design` skill first to calibrate the design effort.
- **In the terminal (Claude Code)**: there is no artifact panel. Write a
  self-contained `.html` file into the repo under `./artifacts/` (create it if
  needed; suggest gitignoring it) and tell the user the path to open. This is
  the graceful-degradation path — same artifact, different renderer.

## Rules for the HTML itself

- **Self-contained.** Inline all CSS and JS. No external stylesheets, fonts,
  scripts, or network requests — artifact surfaces enforce a strict CSP and a
  local file should open with no dependencies. Embed any images as `data:` URIs.
- **Theme-aware and responsive.** Style for both light and dark; use relative
  units and let wide content (tables, diagrams) scroll inside its own container
  rather than the page body.
- **Reproducible.** Put the originating prompt/context in a leading HTML comment
  so the artifact can be regenerated by pasting it back. This is the whole idea:
  the artifact is a cheap, re-runnable probe for an unknown.
- **Lead with what the user reacts to.** The decision, the mockup, the quiz —
  first. Supporting detail below.
